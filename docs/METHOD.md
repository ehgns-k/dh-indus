# 작업 방법과 작업 흐름

## 1. 작업 단위

연구는 서로 독립적으로 진행할 수 있는 여섯 개의 작업 단위로 나눈다. 각 단위는 정해진 입력을 받아 정해진 산출물을 남긴다. 여러 단위를 동시에 진행할 수 있다.

| 단위 | 입력 | 산출물 | 비고 |
|---|---|---|---|
| A. 자료 | 공개 코퍼스 | `data/sources.tsv`, `src/indus/corpus.py`, 대응표 | 원자료는 저장소에 넣지 않고 고정 버전으로 내려받는다 |
| B. 문헌 | 학술 데이터베이스, 출판사 기록 | `docs/BIBLIOGRAPHY.md`, `docs/CLAIMS_REGISTER.md` | 모든 항목에 확인 경로를 남긴다 |
| C. 구조 | A의 정규화 자료 | `results/phase3_*` | 두 코퍼스에서 모두 재현되어야 한다 |
| D. 유형 | A, C | `results/phase4_*` | 대조 모형 필수 |
| E. 언어 가설 | A, C, B의 주장 목록 | `results/phase5_*` | 가설마다 대조 언어 실험 필수 |
| F. 검토 | 다른 단위의 결과 | `reports/REVIEW_*.md` | 결과를 반박하는 역할만 맡는다 |

## 2. 순환 절차

각 작업 회차는 다음 순서를 따른다.

1. `docs/JOURNAL.md`의 마지막 기록과 `ROADMAP.md`를 읽고, 다음에 할 일을 정한다.
2. 가설을 먼저 `docs/JOURNAL.md`에 적고, 그 가설이 맞다면 어떤 결과가 나와야 하는지(예측)를 적는다.
3. 분석 스크립트를 `scripts/`에 작성하고 실행한다. 결과는 `results/`에 자동 생성한다.
4. 결과를 예측과 비교하여 기록한다. 예측과 다르면 다르다고 적는다.
5. 검토 단위(F)가 대조 실험 누락, 자료 누출, 다중 비교 문제 등을 점검한다.
6. 변경 사항을 커밋하고 원격 저장소에 올린다.

## 3. 규칙

- 원자료: 고정된 커밋과 SHA-256으로만 사용한다 (`scripts/fetch_data.py`).
- 읽는 순서: 모든 정규화 자료는 읽는 순서로 저장한다. 근거는 `docs/JOURNAL.md` 2026-11-25 기록을 본다.
- 중복: 같은 문자열이 여러 유물에 찍힌 경우(같은 인장의 각인 등)가 많으므로, 빈도 통계는 기본적으로 중복을 제거한 줄 단위로 계산한다.
- 누출 방지: 원자료에 포함된 기존 해독안(예: ICIT 계열 전사본의 `sanskrit`, `translation` 열)은 분석에 쓰지 않는다.
- 보류 자료: 3단계 이후의 예측 검정에 쓸 보류 자료를 미리 정해 두고, 가설을 세울 때 보지 않는다.
- 다중 비교: 여러 가설을 시험하면 그 수를 기록하고 보정한다.
- 인용: 문헌상의 사실 주장은 `docs/BIBLIOGRAPHY.md`의 항목을 인용한다. 출처를 찾지 못한 주장은 쓰지 않는다.
